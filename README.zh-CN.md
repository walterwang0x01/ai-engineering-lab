# AI Engineering Lab

AI 工程概念的交互式练习场。每个概念都配了**程序能判定对错的题**和**能调参数的沙盒**——
不是又一份读着点头、读完就忘的教程。

全部在浏览器里跑。没有后端，不需要账号，不收集数据。学习进度只存在你自己的 `localStorage`。

[English](./README.md)

---

## 为什么做这个

我写了 571 篇 AI 工程笔记。内容准确、覆盖完整，但完全是惰性的——
读的时候感觉很充实，读完留下的东西不多。

诊断结果：每篇笔记开头的自测题都是开放式的（「说明 X 是怎么工作的」）。
开放式问题无法被程序判定，所以只能自评。而自评有两重失效——
没有即时反馈，而且人会系统性地高估自己。

所以这个项目从一条硬约束出发：**每道题都必须能被机器判定。**
这条约束排除了「谈谈 X 的权衡」这类题，逼出有确定答案的题——
而这反过来也逼出了*更好*的题：真正检验你能不能算出来的那种。

## 设计决定

**可判定，不是自评。** 数值题带明确容差，选择题的干扰项来自真实的常见误解。
判定由程序说了算，不看你的自我感觉。

**答错是入口，不是惩罚。** 第一次错给提示并允许重答，第二次错才展开完整推导。
选错某个干扰项，会得到针对*那个具体误解*的专门解释。

**间隔重复，不是每日打卡。** 答对的题按 1、3、7、16、35 天安排复习。
刻意不做连续登录天数——连击奖励的是「每天来点一下」，
而深度技术内容需要的是「偶尔沉浸两小时」。这两个激励方向相反。

**不做徽章和排行榜。** 一篇[教育软件游戏化的综述](https://arxiv.org/abs/2305.08346)
统计发现，徽章、排行榜、竞赛、积分是最常引发负面效果的四个元素。
这里的受众是在职工程师，给他们发小红花是一种居高临下。
他们真正想要的是知道自己不知道什么。

## 当前内容

**五个关卡，52 道可判定题** —— 反向传播与死亡 ReLU、Tokenizer 与成本、
Attention 与因果掩码、KV Cache 容量规划、RAG 分块与检索质量。
其中 9 道要在浏览器里真跑 Python。五关里有三关是多约束沙盒，
要调参数让所有预算同时成立。

**168 篇笔记接进同一条路径。** 首页的学习路径是单一数据源：
模块和章节来自笔记库，每个关卡挂在它背景阅读所在的章节上。
笔记正向指向配套关卡，关卡反向指回背景笔记。

**笔记里也有可判定题（Tier A）。** 笔记可以携带程序判定的选择题，
与关卡题共用同一个判定引擎和同一套间隔重复调度。目前覆盖 4 篇，
管道和门禁已经就位，剩下的按同样标准逐篇补。

KV Cache 沙盒是个典型：真实服务场景（Llama 2 70B、batch 32、4K 上下文），
两个必须同时满足的预算——显存低于 45 GB、质量损失低于 2%。
12 个配置组合里恰好 3 个能过。你没法靠「每次都选最省的」通关——
MQA 显存最省，但质量上过不去。

## 开发

```bash
pnpm install
pnpm exec playwright install chromium   # 组件测试需要

pnpm run dev          # 开发服务器
pnpm run check:all    # 全部门禁：lint + 类型检查 + 测试 + 冒烟
pnpm run test:smoke   # 构建后在真实浏览器里验证全链路
pnpm run build        # 静态产物输出到 build/
```

### 技术栈

SvelteKit 2 + Svelte 5 runes、`adapter-static`、Tailwind 4、Vitest 4
（单元测试跑在 Node，组件测试通过 Playwright 跑在真实 Chromium 里）。

选它的两个理由：Svelte 编译产物是几 KB 而 React 要约 45 KB gzip，
这一点在后续要加更重的交互功能时很关键；
以及如果将来真需要后端，把 `adapter-static` 换成
`adapter-cloudflare` 或 `adapter-node` 只是改一行。

### 部署

产物是纯静态的。预渲染页输出相对路径，但 SPA fallback（`404.html`）不能——
它会被从任意深度返回，所以 SvelteKit 给它发根绝对路径。**因此部署到子路径必须设
`BASE_PATH`**，否则 fallback 页加载不到任何 JS，所有未预渲染的深层 URL 都白屏，
而预渲染页看起来完全正常。

`scripts/assert-fallback-base.mjs` 跑在每次构建之后，fallback 的资源前缀与
`BASE_PATH` 不一致就让构建失败。部署工作流里设的是 `BASE_PATH: /ai-engineering-lab`。

### 需要知道的约定

完整清单在 **[AGENTS.md](./AGENTS.md)**——参与开发或让 AI agent 改这个仓库之前先读它。
里面每一条都来自真实踩过的坑。摘要：

- **根 `+layout.ts` 里的 `prerender = true` 是 `adapter-static` 的必需项**，删了构建会失败。
- **内部链接必须用 `$app/paths` 的 `resolve()`。** ESLint 会强制检查；
  这也是子路径部署不断链的保障。
- **`QuizCard` 不会因为 `question` 变化而自我重置。** 调用方必须用
  `{#key question.id}` 包裹。这是刻意的——整体重建不留状态残留的余地。
- **题目里的数值由测试保证，不靠人工核对。**
  `kv-cache-questions.spec.ts` 会用 KV Cache 公式独立重算每一道题的答案。
  加了数值错误的题，CI 会拦住。
